What happens when you send a prompt

  1. Plan. The agent calls orchestrator_capabilities to see which providers can run child tasks, then writes goal, phases, file ownership and the acceptance check.
  2. Skeleton. It builds the shared interfaces itself and freezes them. That is what lets parallel agents merge.
  3. Delegate. One delegate_task per disjoint file set. Each becomes a T3 child thread on any provider, with role and a self-contained prompt.
  4. Work the critical path. The parent keeps building the hard parts instead of idling.
  5. Coordinate. task_status reads results, t3_thread_send steers, t3_thread_read inspects, task_cancel stops.
  6. Verify, then merge. The parent runs the acceptance command itself. A child's summary is not evidence.

Who talks to whom

Children are isolated: each gets only its own prompt and cannot see the others. T3 is the bus.
